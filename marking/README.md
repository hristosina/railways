# Marking

Настольное приложение для ручной и автоматической разметки датасетов детекции,
редактирования классов, обучения и тестирования моделей.

Светлая тема интерфейса хранится отдельно в `assets/styles/light.qss`. Она
использует мягкие серо-голубые поверхности, синий акцент, компактные состояния
наведения и скруглённые поля, не меняя информационную структуру экранов. Файл
темы автоматически включается в EXE.

## Открытие датасета

При запуске сразу открывается раздел «Разметка датасета». Для ручной разметки
нужны только папка датасета и `data.yaml` со списком классов. Файл модели `.pt`
не требуется: он используется исключительно для авторазметки.

Можно выбрать корень датасета, папку split (`train`, `valid`, `test`) или саму
папку `images`. Для стандартного Roboflow-датасета приложение автоматически
находит корень и `data.yaml`. В списке разметки отображаются только папки,
содержащие изображения, поэтому выбор служебной папки `labels` больше не
приводит к аварийному завершению.

Разметка отсутствующего `.txt` создаётся при сохранении. Редкие действия собраны
в меню с иконкой над изображением: там можно скопировать разметку предыдущего
файла, удалить все рамки или вернуть сохранённую версию. Операции изменения
рамок поддерживают отмену через `Ctrl+Z`.

Копирование с предыдущего изображения добавляет отсутствующие рамки и не удаляет
существующие (`Ctrl+P`). Несколько рамок выбираются щелчками с зажатым `Shift`.
Выбранные рамки можно перенести через общий буфер приложения: `Ctrl+C`, переход
на другое изображение, `Ctrl+V`. `Ctrl+D` удаляет все рамки текущего изображения
после подтверждения.

Команда «Применить выделенные рамки ко всей папке» находится в меню `other`.
Она добавляет выбранные рамки во все файлы разметки открытой папки, сохраняя
существующие строки и пропуская точные дубликаты. Перед массовой записью
приложение показывает количество рамок и изображений и запрашивает подтверждение.

В том же меню находится команда «Удалить изображение из датасета». После
подтверждения она убирает текущее изображение и парный `.txt` из активного
split, перемещая их в `.marking_trash/images` и `.marking_trash/labels`.
Удаление поэтому можно восстановить вручную. Горячая клавиша этой команды —
`Delete`, если ни одна рамка не выделена; при наличии выделения `Delete` удаляет
только выбранные рамки. Стрелки влево и вправо переходят ровно на одно изображение.
Порядковый номер в нижней строке можно изменить вручную: после ввода номера и
нажатия `Enter` приложение сразу переходит к выбранному изображению.

## Подключение моделей

Рабочий список сравнительного исследования состоит из пяти профилей:
`YOLOv8s`, `YOLOv12s`, `RT-DETR-R18`, `RT-DETRv2-S` и `RF-DETR-Nano`. Обычные
RT-DETR/RT-DETRv2 и DINO из каталога исключены. Точный профиль сохраняется в
параметрах обучения и отчете, поэтому результаты разных архитектур нельзя
случайно перепутать.

YOLOv8s и YOLOv12s имеют рабочий backend Ultralytics. Компактные RT-DETR-R18 и
RT-DETRv2-S используют официальную реализацию `lyuwenyu/RT-DETR`: ее `.pth`,
конфигурации и цикл обучения несовместимы с RTDETR-L/X из Ultralytics. Поэтому
эти веса намеренно не передаются неподходящему загрузчику. RF-DETR-Nano работает
через официальный пакет RF-DETR. Все три transformer-backend-а запускаются из
изолированного `venv310`, поэтому их зависимости не ломают основное окружение и
собранный ранее YOLO-интерфейс.

Окружение дополнительных моделей устанавливается одной командой:

```bat
install_model_backends.bat
```

Скрипт устанавливает совместимые версии CUDA PyTorch, RF-DETR и Transformers,
загружает официальный репозиторий RT-DETR и выполняет итоговую проверку. В
текущем проекте проверены Python 3.10.11, PyTorch 2.5.1+cu121, RF-DETR 1.5.2 и
Transformers 4.57.6. Обновлять RF-DETR/Transformers по отдельности нельзя: новые
версии требуют другой версии PyTorch. Предобученные веса RT-DETR-R18,
RT-DETRv2-S и RF-DETR-Nano приложение скачивает автоматически при первом
обучении; вручную выбирать их необязательно.

YOLO-разметка перед официальными RT-DETR автоматически преобразуется во
временный COCO JSON внутри папки запуска. Исходные изображения и `.txt` при этом
не копируются и не изменяются. RF-DETR читает тот же YOLO-датасет напрямую.

Для каждого профиля отдельно отображается статус проверки RKNN. Наличие ONNX-
экспорта не считается подтверждением совместимости: окончательное решение о
составе исследования принимается после конвертации RKNN Toolkit2 и запуска на
целевом устройстве.

Анализ динамики обучения поддерживает обе схемы ошибок: `box_loss` для YOLO и
сумму `giou_loss + l1_loss` для RT-DETR. Абсолютные значения этих функций потерь
между архитектурами сравнивать нельзя, но тенденции train/validation и признаки
переобучения оцениваются единообразно.

Редактор вызывает модели через единый каталог профилей. Ultralytics работает в
основном процессе, а официальные RT-DETR и RF-DETR — через sidecar-процесс с
JSON-протоколом прогресса. Поэтому вкладки обучения и тестирования не зависят от
конкретной библиотеки, а формат сохранения параметров и отчетов одинаков для
всех пяти архитектур.

Формат хранения рамок пока остаётся YOLO (`class x y width height`), поскольку
это формат подготовленного датасета. Он не ограничивает архитектуру модели:
адаптер преобразует результат конкретной модели в единый объект `Detection`.

Все иконки интерфейса находятся в `assets/icons`. При добавлении новой иконки
её следует сохранять в эту папку; сборка включает PNG-файлы оттуда автоматически.

## Оценка завершенного обучения

После завершения обучения приложение автоматически читает `results.csv` из
папки запуска и анализирует сглаженную динамику последних 20% эпох (не более
20 и не менее 5). Основные признаки — изменение `train/box_loss` и
`val/box_loss`; дополнительно учитываются `mAP@0.5:0.95`, лучшая эпоха и разрыв
между train и validation.

В результате показывается одна из рекомендаций: продолжить обучение,
продолжить осторожно, остановиться из-за плато, проверить возможное
переобучение либо сначала проверить данные и настройки. Значения и объяснение
сохраняются рядом с `results.csv` в файле `Анализ_обучения.txt`. Это
диагностическая эвристика, а не математическая гарантия: окончательное решение
следует подтверждать независимой тестовой выборкой и метриками отдельных
классов.

## Статистика датасета

Кнопка «Сформировать статистику датасета (Excel)» без иконки показывается только
на вкладке «Редактирование датасета». Книга `Статистика_датасета.xlsx` сохраняется в корне набора и
содержит листы `Train`, `Val`, `Test` с количеством изображений, числом объектов
каждого класса и встроенными диаграммами со стандартной числовой шкалой Excel.
Лист «Сценарии test» строит общую
диаграмму по погоде и времени суток; сценарии определяются по готовым папкам или
префиксам имен файлов Roboflow. Лист «Проблемы» перечисляет отсутствующие и
пустые файлы разметки, некорректные строки и неизвестные ID классов.

После успешного обучения такая же книга автоматически сохраняется в папке
конкретного запуска рядом с `results.csv`, весами и `Анализ_обучения.txt`. В ней
зафиксированы абсолютные пути к корню датасета и `data.yaml`, поэтому для каждой
модели можно восстановить, на какой версии данных она обучалась.

В начале каждого запуска там же создаётся `Параметры_обучения.yaml`. В нём
сохраняются выбранная архитектура и начальные веса, датасет, количество эпох,
размер изображения, batch, patience, устройство, число workers, версии среды и полный
набор фактических параметров backend-а. После успешного окончания статус и время
завершения в файле обновляются. Поэтому параметры остаются доступны и для
сравнения запусков разных поддерживаемых архитектур.

Для восстановления прерванного запуска включите «Продолжить прерванное
обучение из checkpoint» и выберите `weights/last.pt`. В этом режиме Ultralytics
восстанавливает номер эпохи, optimizer и расписание learning rate; целевое число
эпох берётся из checkpoint, поэтому поле эпох блокируется. Если флажок снят,
любой совместимый `.pt` используется как начальные веса нового отдельного
дообучения с новым optimizer и указанным в интерфейсе числом эпох. `best.pt` не
следует использовать для режима resume.

Для RT-DETR выберите `best.pth` или последний checkpoint из папки запуска, для
RF-DETR — `checkpoint.pth`. У transformer-моделей поле «Количество эпох» в
режиме продолжения означает общее целевое число эпох и остается доступным.

На Windows обучение запускается с `workers=0`: загрузка данных выполняется в
основном процессе. Это исключает многократную загрузку PyTorch/CUDA дочерними
процессами и ошибку `WinError 1455` при пересоздании dataloader перед
отключением mosaic. На других ОС число workers выбирается автоматически и
ограничивается восемью.

## Восстановление сценариев тестовой выборки

Выгрузку Roboflow рекомендуется сохранять как основной неизменяемый YOLO-набор.
Для тестов по погоде и освещению отдельное представление создаёт скрипт:

```powershell
python tools\organize_test_scenarios.py D:\path\to\Railways_v1.yolov8
python tools\organize_test_scenarios.py D:\path\to\Railways_v1.yolov8 --apply
```

Первый запуск — безопасный dry-run. Второй создаёт рядом папку
`test_scenarios` с подпапками `afternoon`, `night`, `twilight`, `fog`,
`fallout`. По умолчанию используются жёсткие ссылки: данные не дублируются и
исходный `test/images` не изменяется. Если жёсткие ссылки недоступны, добавьте
`--strategy copy`. Для вкладки тестирования выбирайте папку `test_scenarios`.

То же восстановление доступно непосредственно на вкладке тестирования. После
выбора корня Roboflow-датасета приложение сначала ищет готовую папку
`test_scenarios`. Если её нет, оно распознаёт сценарии по префиксам имен файлов
и предлагает создать представление после показа количества изображений.
Отдельная кнопка восстановления с иконкой сброса находится под таблицей
сценариев. При невозможности создать жёсткую ссылку приложение автоматически
переходит к копированию; исходные `train`, `valid` и `test` не изменяются.

## Отчет о тестировании модели

На вкладке «Тестирование модели» укажите модель и `data.yaml`. Сценарии задаются
явно в таблице: название можно изменить, а для каждой строки необходимо выбрать
конкретную папку с подпапками `images` и `labels`. Изначально добавлены строки
«Осадки», «Туман», «День», «Ночь» и «Сумерки»; их можно удалить или дополнить
собственными сценариями. Общая папка датасета используется только для
автоматической подсказки известных путей и не добавляет `train`, `valid` или
`test` в отчет самостоятельно.

Для каждого сценария выполняется один валидационный прогон. Служебные файлы
Ultralytics создаются во временном каталоге и автоматически удаляются, поэтому
папки `runs/detect/val*` не накапливаются. Папка итогового отчета выбирается в
интерфейсе.

В выбранную папку сохраняется одна книга `Отчет_тестирования.xlsx` и по одному
готовому PNG-графику Precision–Recall для каждого сценария. Лист «Результаты»
повторяет структуру таблицы диплома —
сценарий, класс, `mAP@0.5`, `mAP@0.5:0.95`; лист «Сводка» содержит общие метрики,
скорость и число изображений, а «PR данные» — исходные точки графиков.
Стандартные графики Ultralytics также сохраняются, но собираются в одну плоскую
папку `Стандартный_отчет_Ultralytics`; имя каждого файла содержит название
сценария. Повторный запуск обновляет эти же файлы и не создает папки с номерами.
Для RT-DETR и RF-DETR рядом создается одна папка
`Стандартный_отчет_<архитектура>` с COCO-разметкой сценариев, предсказаниями и
машиночитаемым `metrics.json`; общий Excel и PR-графики имеют ту же структуру,
что и для YOLO.

Перед расчетом приложение сравнивает порядок классов в выбранном `data.yaml` с
порядком, сохраненным внутри обученной модели. Это важно после повторного
экспорта из Roboflow: платформа может изменить числовые ID классов, хотя их
названия останутся прежними. При различии порядка приложение создает временное
представление разметки с корректными ID; исходные `.txt` не изменяются. Порядок
обоих источников и выполненное соответствие ID записываются в листы «Параметры»
и «Соответствие классов» итоговой книги.

## Сборка EXE

`create_exe.bat` запускает PyInstaller из каталога проекта и использует
`marking.spec`, который включает все PNG-ресурсы. Если перенесённое `venv`
ссылается на удалённую версию Python, его необходимо пересоздать и установить
`requirements.txt`; скрипт сборки теперь сообщает об этом явно.
